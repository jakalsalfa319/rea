# REA + OpenCode research lab — agent rules

This `lab/` directory is a controlled software-analysis testbench. It is NOT a production MINT WORLD/TREKT checkout.

1. Work on the `lab/rea-opencode-codespaces-20261111` branch. Never switch, merge or push to `main` without explicit permission.
2. Analyse only the included owned fixture, your own projects, open-licensed targets, or targets whose examination is explicitly authorised. Do not collect secrets, bypass access controls, or copy proprietary source, games, artwork, models, sounds, credentials or licences.
3. Write `lab/.reports/investigation.md` with target, authorisation/licence, exact versions, commands, observations, source references, unknowns and confidence before implementation.
4. Implement independently, keeping reference material separate from deliverable code. Never confuse decompiled pseudocode with original source.
5. Verify file existence, execute the fixture tests, run REA inspection and report passing/failing cases. Never claim installation, deployment or functional equivalence without confirming it.
6. Use the smallest necessary tools; ask before modifying global configurations, downloading binary analysis providers, using paid APIs, or sending project/private data to external providers. Never store API tokens in the repository.
7. Prioritise reproducible, reversible steps and version control checkpoints. Stop on failed verification instead of concealing failures.
